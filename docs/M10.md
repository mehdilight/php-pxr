# M10 implementation status

M10 is in progress. This file records independently testable slices; it does
not narrow the scope in [MILESTONES.md](MILESTONES.md).

## Implemented slices

- Synchronous and async by-value closures and arrow functions support capture snapshots,
  escaping/nested environments, return inference and lifetime across await.
  Captured local mutations reset per invocation; shared objects retain identity.
  See [CALLABLES.md](CALLABLES.md) for syntax and explicit remaining restrictions.

- Trait closures support static scope and lexical `self`/`parent` annotations,
  including generic consumers, nesting and async execution.
- Generic function/class/method closure scopes retain enclosing type parameters
  and bounds, including type-only parameters, nested environments and async bodies.
- Closure parameter/return annotations bind `self` and `parent` to the declaring
  class, including its generic arguments and nested container/ownership annotations.
- Bound closures preserve class visibility, `self`/`parent` context,
  overridden method dispatch, nested captures and instance/static trait scope. Static
  closures do not capture `$this`. Shared receivers survive suspension and async
  creator-frame exit; implicit owned/borrowed receiver capture is rejected.

- Invokable objects support `$callback($value)`, parenthesized receivers,
  constructor/function-result receivers and typed interface callbacks. Existing
  virtual dispatch, ownership and GC rules apply. Receiver expressions evaluate
  once before arguments, including arguments that await. `__invoke` remains
  synchronous and cannot declare method-level generics under current magic-method
  rules. Callable strings/arrays, generic `callable` annotations, first-class
  references are not implied by this support.

- Keyed foreach preserves integer/string keys, insertion order and snapshots.
  Keys use mixed storage, including binary strings; mixed key access checks tags.
- Reads through mixed array values/properties check each container at runtime;
  nested reads and interpolation preserve boxed element values. This remains
  array access: string offsets and scalar/null coercion are outside this slice.
- Nested writes support typed arrays, mixed arrays/null, object and static
  properties, deep appends, COW snapshots, and single evaluation of target keys
  and receivers before the right-hand side. Prepared targets survive suspension.
- Assignment, compound assignment, coalescing assignment and prefix/postfix
  numeric increments produce expression results. Assignment is right associative.
  Ownership checking rejects duplication of owned or borrowed bindings.
- Definite initialization rejects reads after skipped assignments/branches and
  zero-iteration foreach loops. Expression writes invalidate mixed type guards.
- Interpolation supports simple array keys/property names and braced nested
  access/method calls, using the ordinary expression parser. Deprecated syntax
  and invalid forms remain explicit errors.

- Nullable and union annotations, including `?T`, `T|null`, standalone null/boolean
  literals, and failure returns such as `string|false`, use checked tagged storage.
  Generic substitutions, typed arrays, class membership, closures and async worker
  serialization preserve the union contract. Native affine resources remain
  excluded from union storage; invalid declarations and values are explicit errors.

- Explicit `--compat` mode supports untyped parameters/properties, bare arrays,
  changing ordinary locals and mixed returns, with checked native boundaries.
  See [COMPATIBILITY.md](COMPATIBILITY.md) for the exact contract and restrictions.

- Optional positional parameters support functions, methods, constructors,
  closures, generics and async calls. Virtual dispatch selects implementation
  defaults; see [ARGUMENTS.md](ARGUMENTS.md) for the supported default expressions.

- Named arguments bind functions, methods, constructors, closures, generics,
  async calls and supported native builtin operands while preserving source
  evaluation order, snapshots and borrow checks. Current virtual-name and
  intrinsic restrictions are documented in [ARGUMENTS.md](ARGUMENTS.md).

## Outstanding acceptance work

- First-class callable references, general callable
  strings/arrays and annotations, and persistent reference-capture alias semantics.
  Ordinary bound/static closures and invokable object/interface callbacks work.
- Throwable/throw/try/catch/finally, propagation, rooted unwinding and affine
  cleanup, including async failure/cancellation behavior.
- Variadic arguments and unpacking.
- Generators and iteration protocols, with independent acceptance fixtures.
- Attributes, with independent acceptance fixtures. `#[...]` currently produces
  E0009 instead of being silently discarded as a line comment.

## Validation

CLI tests compare the supported PHP syntax directly with the installed PHP
interpreter. Async acceptance tests exercise prepared targets and expression
results at optimization levels 0 and 3, both with ordinary and forced GC.
Runtime sanitizer suites also cover these tests. Full validation results are
recorded with each implementation checkpoint.

## Compatibility policy

Strict native compilation remains the default: explicit parameter types,
`array<T>` element types, and fixed storage types for inferred concrete locals.
`mixed` is the supported way to request changing value types; guards narrow
values without changing that storage representation. The explicit `--compat` build mode uses
mixed storage for untyped parameters, bare arrays and changing ordinary locals,
with checked boundaries into concrete code. Strict compilation remains the
default; see [COMPATIBILITY.md](COMPATIBILITY.md). PHP aliases/reference captures require a separate lifetime
contract and cannot be represented by call-scoped borrows.

A runnable shared-syntax example is
[`compat_foundations.php`](../examples/compat_foundations.php).

Reference semantics: [PHP foreach](https://www.php.net/manual/en/control-structures.foreach.php)
and [PHP arguments](https://www.php.net/manual/en/functions.arguments.php).

### Bound and static closure extension — 2026-10-17

Closures preserve lexical member access, inherited dispatch, nested receiver
binding and instance trait scope. Static closures do not retain an instance.
An overridden trait factory does not instantiate its discarded closure body.
Internal forwarding preserves inferred void, owned parameters/returns and
borrowed argument contracts, including trait copies with identical contracts.
The complete workspace run passed 304 tests. Focused closure/ownership sanitizer
fixtures and the worker ThreadSanitizer case also passed.

PHP differential fixtures cover these behaviors. Async acceptance covers temporary
receivers, returning closures after an async creator suspends, and worker-local
heaps/statics. ASan/UBSan and ThreadSanitizer cover the new worker fixture;
ASan/UBSan covers retained environments and ownership forwarding at O0/O3 with
forced GC. `make check` and `make examples` cover the updated closure example.

At this checkpoint, generic lexical type binding, static trait scopes, async
closures, reference captures and general callable forms remained unfinished.
The async extension below supersedes the async-closure limit. M10 remains in progress.

### Lexical closure annotation extension — 2026-10-17

Non-generic class closures bind `self` and `parent` in parameter and return
annotations before moving them into environment classes. Inherited factories
retain the declaring type, and parent annotations retain concrete generic
parent arguments. Nested containers, owned transfers and borrow parameters
preserve the same binding. Missing parents, unrelated argument/return types,
trait annotations and late static binding produce explicit errors.

Focused acceptance passes PHP comparison, O0/O3 normal/stress GC, and
ASan/UBSan for the new async and ownership fixtures. `make check` passes.

### Async closure extension — 2026-10-17

`async function` and `async fn`, with optional `static`, create native lazy tasks
on invocation. Captures snapshot at closure creation; arguments snapshot at task
creation. Bound/nested/trait scopes, inferred and explicit void, moved owners,
spawn, failure propagation, cancellation and scope cleanup use the existing task contract. User magic
methods remain synchronous. Call-scoped borrow parameters and owned/borrowed
captures remain errors. This is PXR syntax, not PHP syntax.

Acceptance exercises O0/O3 normal/stress GC, lazy side effects, nested results,
retained temporary receivers, async creator-frame exit, owned forwarding, lazy
and started cancellation, and worker-local heaps/statics.

The workspace suite passes 314 tests. The four async closure fixtures pass
ASan/UBSan at O0/O3 with normal/stress GC; the worker fixture passes
ThreadSanitizer. The extended failure/owned cleanup fixture and stricter negative
checks also pass. `make check` and `make examples` pass, including the new
[`async/closures.php`](../examples/async/closures.php) example.

Class-scoped async closures currently await an internal scope bridge, adding a
task/frame per invocation. Generic lexical binding, static trait scope, general
callable forms, aliases, exceptions, broader types/arguments and the remaining
acceptance items above are still unfinished; M10 remains in progress.

### Generic lexical closure extension — 2026-10-17

Closures retain enclosing function, class and method type parameters, including
parameters used only in annotations and dependent interface bounds. Generated
environments specialize with both lexical types and captured value types. A
static factory binds known lexical types before inferring captured value types;
no runtime type erasure or ownership-check bypass is introduced. Bound bridges
retain the declaring class specialization and method generic arguments.

Acceptance covers nested closures, module/import isolation, generic `self` and
`parent`, inherited private access and virtual dispatch, instance trait generic
methods, owned transfers and borrowed parameters, and async creator-frame exit.
Wrong argument/return types, unsatisfied bounds and escaping owned/borrowed
captures still produce errors. Static trait closures and lexical trait type
annotations remain unfinished, along with the outstanding work above.

The workspace suite passes 321 tests. Generic closure async-lifetime and ownership
fixtures pass ASan/UBSan at O0/O3 with forced GC (async also runs normal GC).
`make check` and `make examples` cover the new generic closure example and
the async generic example. M10 remains in progress.

### Trait lexical closure extension — 2026-10-17

Static trait closures and `self`/`parent` annotations now bind to each consuming
class. Inherited factories retain the original consuming declaration; nested
trait composition and closures preserve that scope. Compiler-only type witnesses
bind after composition, before specialization, without capturing a receiver in
static environments. Generic consumers keep their class arguments even when an
imported trait method uses the same parameter name. These additions supersede
the trait restrictions recorded in earlier checkpoints.

Ownership return inference resolves the same witnesses before checking invariant
borrowed arrays; incorrect consumer/parent types remain errors. Owned transfers,
static closures escaping dropped owners, async creator-frame exit, cancellation
and per-worker static storage have independent acceptance fixtures. Discarded
overridden trait factories do not instantiate their unused nested closure bodies.

Shared syntax is compared directly with PHP. The new async fixtures pass
ASan/UBSan at O0/O3 with normal/stress GC, and the ownership fixture passes
ASan/UBSan at O0/O3 with forced GC. The new worker fixture passes ThreadSanitizer.

The workspace suite passes 329 tests. The extended generic shadowing/borrow
fixture also passes ASan/UBSan. `make check` and `make examples` pass; the new
[`trait_closures.php`](../examples/trait_closures.php) example produces identical
output in PHP and PXR. M10 remains in progress.


### Nullable and union types — 2026-10-17

Annotations support nullable shorthand, union members, and standalone `null`,
`false` and `true`. Nullable shorthand cannot be combined with a pipe; use the
explicit `T|null|U` form. Duplicate/redundant concrete declarations and
`mixed`/`void`/affine resources in unions are rejected. Generic substitutions
normalize duplicate or redundant members introduced by specialization.

Tagged values validate membership at arguments, returns, assignments and property
writes. Arrays validate nested element types and rebuild native typed views
without changing keys/order or copy-on-write snapshots. Narrowed array writes
validate before publishing back to union storage. Class membership uses normal
inheritance/interface checks. Integer-to-float widening is supported at scalar
boundaries; arrays do not silently widen elements. This native contract does not
add PHP's weak scalar coercions or full PHP variance rules.

Closures, precise GC roots, await frames, ownership checks and isolated worker
serialization recognize the representation. Runtime union failures currently
terminate with TypeError; catchable exceptions remain outstanding below.

Acceptance: 338 workspace tests; O0/O3 ASan/UBSan union CLI, async and ownership
fixtures, with normal/stress GC for async; worker ThreadSanitizer. `make check`
and `make examples` pass. Generic boolean specialization has an additional
acceptance case. M10 remains in progress.

Reference: [PHP type declarations](https://www.php.net/manual/en/language.types.declarations.php).


### Explicit compatibility mode — 2026-10-17

`--compat` applies consistently to checking, native builds/runs, AST/IR/LLVM
artifacts and migration reports, including native modules. It normalizes source
annotations and implicit null returns before creating closure adapters. Compiler
capture slots retain their own types. Untyped property defaults, including
statics, initialize to null. Tagged numeric increments validate before mutation.

Typed boundaries share the union runtime descriptor/validation implementation.
Borrow markers are preserved; no runtime reboxing can hide a borrow conversion
from the final representation checker. Native resources/tasks keep affine
storage. Known object facts permit direct native object/closure dispatch without
adding arbitrary dynamic member resolution.

Acceptance covers direct PHP comparisons, mode opt-in, invalid dynamic tags and
nested array/object types, explicit annotations and borrow rejection, module
loading and every supported CLI artifact. Async fixtures cover suspension,
closure/array snapshots, retained objects and worker isolation at O0/O3 with
normal/stress GC. Both pass ASan/UBSan; the worker fixture also passes
ThreadSanitizer. M10 remains in progress.

The workspace suite passes 344 tests. `make check` and `make examples` include
`examples/compat-mode/main.php`; its output matches PHP directly. Checked native
boundaries also cover class-qualified methods and typed async/I/O configuration
operands; the async sanitizer fixture uses an untyped sleep duration.


### Optional positional parameters — 2026-10-17

Declarations retain defaults through generic specialization and closure adapters.
Calls pass internal argument-presence storage; the effective function initializes
omitted parameters before executing user code. Compiler-only placeholders never
enter user code. This keeps overridden defaults, skipped failing defaults and
per-call array snapshots correct without evaluating defaults at the call site.
Full-arity adapters preserve the existing native worker/server callback ABI.

Acceptance compares shared syntax directly with PHP, including inherited and
interface defaults, constructors, closures and a base default whose expression
would fail if evaluated. Native tests cover generic function/method/trait closure
scopes, typed union arrays, wrong/default argument diagnostics and ownership
restrictions. Async acceptance covers suspension, owned required prefixes,
interface dispatch, generic closures, isolated workers and server callbacks.
All three async fixtures pass ASan/UBSan at O0/O3 with normal/stress GC; the worker
fixture passes ThreadSanitizer. The workspace suite passes 351 tests.
Named/variadic/unpacking, broader default-expression forms and the other
outstanding work remain incomplete; M10 remains in progress.

`make check` and `make examples` include the new optional-argument example,
whose output matches PHP. Follow-up checks cover trailing commas, compatibility
mode, required mutable-borrow prefixes, native dispatch to overrides that add a
default, rejected incompatible explicit virtual constructors, and conservative
validation of computed failure-literal defaults. Lazy cancellation and supplied
arguments skip a failing default while releasing captured owners under sanitizers.


### Named argument binding — 2026-10-18

Labels survive parsing, module offsets, generic expansion and ownership erasure.
Binding records both parameter positions and source evaluation order. Supplied
values and their snapshots evaluate once in source order; omitted native slots
still initialize inside the effective implementation. Receiver evaluation precedes
arguments, including suspension. The final borrow representation checks inspect
the original argument markers after reordering.

Native builtin signatures use PHP 8.4 operand names. Skipping `array_slice`'s
length before naming `preserve_keys` retains the omitted-length flag. Unsupported
native API options, named intrinsic/PHP-boundary calls and ambiguous virtual
parameter-name changes remain explicit errors. This does not add variadic or
unpacking support.

Acceptance covers PHP differential output, side-effect order, array snapshots,
assignment-dependent initialization, case-sensitive keyword labels, native modules,
generics, traits/interfaces, required borrow prefixes and compatibility mode.
Async fixtures exercise awaited argument order, retained receivers, builtin string
roots, source-ordered loans and isolated workers at O0/O3 with normal/stress GC.
Both async fixtures pass ASan/UBSan; the worker fixture passes ThreadSanitizer.
The workspace suite passes 360 tests. `make check` and `make examples` pass,
and the named-argument example matches PHP. M10 remains in progress.
