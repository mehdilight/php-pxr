# Copy-on-write arrays — 2026-10-16

Array value copies now share entry and hash-index storage until a write needs
independent storage. The 100,000-copy benchmark fell from 257.326 ms to 8.210 ms
(**31.34× faster** than the previous PXR runtime). Copying and then overwriting
two entries fell from 28.607 ms to 16.834 ms (**1.70× faster**). Both copying
benchmarks keep the source array unchanged and validate output against PHP.

| Workload | PXR before | PXR after | PXR improvement | PHP after |
| --- | ---: | ---: | ---: | ---: |
| Startup / print | 2.452 ms | 2.442 ms | 1.00× | 29.893 ms |
| Recursive fib(30) | 4.584 ms | 4.468 ms | 1.03× | 89.097 ms |
| Integer loop (5M) | 2.297 ms | 2.317 ms | 0.99× | 82.416 ms |
| Integer-array append + reads (10k) | 3.035 ms | 3.112 ms | 0.98× | 29.339 ms |
| String-key array writes + reads (5k) | 4.056 ms | 4.060 ms | 1.00× | 29.574 ms |
| Read-only array copies (100k × 1k items) | 257.326 ms | 8.210 ms | 31.34× | 30.405 ms |
| Array copy + two overwrites (10k × 1k items) | 28.607 ms | 16.834 ms | 1.70× | 40.867 ms |
| String append (50k) | 187.741 ms | 187.149 ms | 1.00× | 30.197 ms |
| Objects + methods (2M) | 281.792 ms | 290.750 ms | 0.97× | 189.499 ms |

An improvement above 1 means PXR became faster. Results outside the copying
workloads are not evidence of an optimization. The object workload was about 3%
slower in this run, and remains slower than PHP; string append is also still
slower than PHP. A GC prepass required for shared array storage is skipped when
the heap contains no array headers to avoid scanning an object-only heap twice.

## Method and reproduction

* Apple M3 Max, 36 GiB, macOS 15.8.1 arm64; Apple clang 17.0.0.
* PHP 8.4.25 CLI with installed Herd settings, CLI OPcache off and JIT disabled.
  PXR release compiler, programs built with `--opt 3`.
* Two warmups and nine measured runs per runtime. Execution order alternates
  PXR/PHP; timings include process startup and teardown and exclude compilation.
* Both reports use identical sources and outputs for all nine workloads. The
  new copy-and-write workload also runs under the saved baseline compiler.
* The baseline is revision `137d040`. The after report uses the modified runtime.
  Raw reports record binary SHA-256 values; their git revision is the workspace
  HEAD before the optimization commit. No test suites ran during these timings.

```sh
# Save the baseline compiler before rebuilding the modified runtime.
cp target/release/pxr /tmp/pxr-before-array-cow
cargo build --release -p pxr
python3 benchmarks/bench.py --pxr /tmp/pxr-before-array-cow \
  --repeat 9 --warmup 2 --json /tmp/array-cow-before.json
python3 benchmarks/bench.py --repeat 9 --warmup 2 \
  --json /tmp/array-cow-after.json
```

[Before raw samples](2026-10-16-array-cow-before.json),
[after raw samples](2026-10-16-array-cow-after.json).
To reproduce later, build revision `137d040` separately and select it with
`--pxr`, then build this optimization revision for the second run.

PHP startup is about 30 ms and PXR startup about 2.4 ms in this environment.
End-to-end results do not establish array throughput in a persistent server or
application-wide speedups. The [array-index report](2026-10-16-array-index.md)
and [original M7 comparison](2026-10-16-m7.md) remain available for history.

## Implementation and correctness

* Copying allocates an array header and retains the shared entry/index buffers.
  The first write separates shared storage, copying nested array headers without
  recursively copying their payload buffers. Objects keep PHP reference identity.
* Already boxed mixed arrays use the same sharing strategy. Initial typed-to-mixed
  conversion still normalizes entries and therefore takes linear time.
* Each shared entry buffer is traced once by GC. Unused entry capacity stays zero.
  Dead array headers release buffer ownership before any backing buffers are swept,
  regardless of allocation order. Ownership counters belong to each thread's heap;
  workers continue to transfer serialized values between isolated heaps.
* Nested HTTP parameter insertion and REQUEST merging separate parent storage
  before descending. GET, POST and REQUEST stay independent. Response-header
  replacement clears removed slots and restores packed-key metadata.
* Native tests cover constant-size copies, separation, hash indexes, nested mixed
  arrays, collection of dead copies, live descendants and callback GC guards.
  Source tests cover PHP-equivalent nested mutation, objects, foreach snapshots,
  array transforms and task captures/results across suspension.

Validation: 267 workspace tests and 69 ASan/UBSan checks passed, plus the
native ThreadSanitizer suite and four worker source tests under ThreadSanitizer.
The release build, checks for every example and running every example also passed.
